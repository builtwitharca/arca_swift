hv, in ic's session (18 Oct 2026), trying Gtools.app's masthead after its adoption: "One small error: selecting the masthead if the About window is already open should bring it to the front. Raise that as an issue."

**What happens:** with the About window open behind another app's windows, choosing the masthead row again does not bring the window to the front.

**Where:** `AboutWindow.show(_:title:)` (Sources/ArcaMasthead/AboutWindow.swift). It sets the new page, then calls `NSApp.activate()` and then `window.makeKeyAndOrderFront(nil)`.

**The likely cause, to measure first:**
- `NSApp.activate()` is macOS 14's cooperative activation, which the system does not always grant an app with no Dock icon, as a menu bar app is. The window is then ordered front only within an app that is not active.
- Gtools.app's own windows, its console and settings, come forward with `makeKeyAndOrderFront(nil)` then `NSApp.activate(ignoringOtherApps: true)`, and they do come to the front.

**The fix:** the About window comes to the front whenever the row is chosen, open or not, eg by ordering it front regardless and activating the app in the way those windows do. It's checked by eye:
- in the example app (`swift run ArcaMastheadExample`), with the window behind another app's window when the row is chosen;
- in Gtools.app, once it takes the release.

**The release:** 0.1.1, a fix inside 0.1, which every adopter's `.upToNextMinor(from: "0.1.0")` allows. Each app then moves its resolved version to 0.1.1, Gtools.app first.

**Size:** XS.


**Closed with no code change, not reproduced (19 Oct 2026):**
- **Measured first, in the example app,** on 42ee0e3. Its library code is 0.1.0's, since only the example's files have changed since then.
  - A probe build of the example logged each choice of the row: whether the app was active, the window's key and visible state, the frontmost app and the order of the windows on screen.
  - In hv's trial, the window was open behind another app's window, and the row ran the shipped sequence, `NSApp.activate()` then `makeKeyAndOrderFront(nil)`. The window came to the front every time, this issue's case included, and hv's verdict was "Yep, worked a treat".
  - So the activation was granted, and the suspected cause did not hold. The probe was never committed.
- **In Gtools.app,** hv checked the same case on the installed build 1740 (Gtools 0.5.0, 483b53bf), which uses arca_swift 0.1.0: "And yes, it does come to the front."
- **So 0.1.1 carries issue 0002's fix alone.** If the window is seen behind again, this issue reopens with the case that shows it.
