# ST0001: Shared Swift libraries for the menu bar apps: Masthead, then LogConsole

## Objective

hv's four menu bar apps (menuz, Gtools.app, Intent.app and Conflab.app) share one top line and About panel, and then one log console, from this public Swift package. Each app imports only what it uses, and what the top line and the About panel say comes from files that change without a rebuild.

## Context

hv, 18 Oct 2026: the four menu bar apps' top lines "all seem to be subtly different", so "normalise this functionality across the four apps into a single codebase that each one uses".

- **The top line** has two lines: a heading, which is the app's name and version, and a smaller subheading.
- **It is selectable,** and opens an About panel that renders Markdown or HTML.
- **Both are configured from files,** so a change needs no recompile.
- **It is reusable in other Swift projects,** as Arca's first Swift.

hv then folded the log console in: "Yes. Most definitely. ... And it would have: mastehead, logconsole, etc."

hv's calls:
- macOS only, with Tahoe (macOS 26) as the floor. WebKit's SwiftUI web view needs it.
- A `masthead.yaml` per app, with a default in the bundle.
- The About page in a web view, with Markdown through cmark-gfm.
- This public repo, so CI costs nothing.
- Each app's heading, subheading and own rows worked out from what it shows today.

Measured, 18 Oct:
- All four apps build the row by hand, as a disabled bold 13 pt menu item, from different sources. menuz reads its bundle's stamps, Gtools.app and Intent.app read their CLI's `version`, and Conflab.app shows the signed-in user.
- All four target macOS 14.0.
- Gtools.app's and Intent.app's consoles are separate copies that have drifted apart, at about 500 and 690 lines of Swift, and menuz was to get a third.
- Conflab.app has its own About tab in its Settings window.

`design.md` holds the design as agreed. The work packages build the package first, Masthead and then LogConsole. Each app's adoption is a work package of its own, rolled out selectively, and each is done by that project's IC from ic's brief, in its own repo and under its own gates.
